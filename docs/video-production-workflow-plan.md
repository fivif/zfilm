# video-production × Zfilm 完整视频工作流规划

状态：规划稿，待实施。核对日期：2026-11-12。
对象：本仓库（Zfilm 0.3.6）与本机 video-production 技能。
本轮仅做能力核对及方案设计；未启用新技能、未改动应用代码、未启动成片制作，也未干预现有素材导入任务。

## 1. 判断与目标

可以配合。video-production 负责选题、事实证据、稿件、导演与声音设计、制作规范和验收；Zfilm 负责可见的项目、素材、画布、可编辑时间轴、预览与导出；当前选择的 Agent 负责按阶段完成具体任务。

现有两部分具备互补基础，但还没有自动衔接。把 SKILL.md 塞进聊天，不等于已经拥有可恢复的完整生产线。目标是用户提交资料与用途后，能在同一项目看到脚本、素材选择、有声样段、完整粗剪、审片问题、修改版本和最终交付；失败能定位到具体任务，重试保留已有成功结果。

第一期以真实素材＋少量代码动效的 30–60 秒短片作为验收工程。该时长是集成验收范围，不是对用户所有影片的限制。后续再扩展多画幅和长片。

## 3. 用户看到的完整流程

设置两个主要 AI 输入入口：①资料到脚本/分镜/采集规划；②承接脚本到成片制作/复核/交付。默认简洁提示词，只交代目标、输入和必要边界，让模型结合技能判断方法。两者通过可编辑脚本和必要批注交接；稳定 ID、来源清单和 planning-handoff 按项目复杂度采用，不要求每次填写完整表单。已有脚本可直接从第二入口开始。简洁版与详细参考见 [video-production-prompts.md](video-production-prompts.md)。目前可使用现有 Agent 聊天，这一设计不表示两个新输入框已经实现。

需求/资料 → 素材与证据 → 可编辑脚本 → 导演/声音/分镜 → 有声样段 → 完整粗剪 → 审片修复 → 成片与工程交付。

| 阶段 | Agent 的具体工作 | Zfilm 中可见的产物 | 通过条件 |
| --- | --- | --- | --- |
| 立项 | 理解用途、受众、主线、时长画幅、必须保留项、声音选择；记录假设和缺口 | 项目概要、交付目标、当前阶段 | 主张可理解，关键未知项明确 |
| 素材与证据 | 导入；检索候选；对入选片段实际查看/听音；核对事实和使用依据 | 素材卡、代理预览、可用区间、证据/缺口清单 | 事实与参考分开，不能用文件名或摘要冒充证据 |
| 脚本 | 写可编辑稿件和故事链，按稳定段落 ID 连接事实与画面 | 文稿、镜头需求、用户批注 | 主要内容有依据，缺镜头变采集任务；无旁白需求不生成 TTS |
| 导演与分镜 | 选择 1–3 个风格候选；安排动作、文字、音乐落点、镜头接力与素材入出点 | 画布分镜、风格说明、音乐结构与镜头表 | 内容/重复审计通过；参考不充当产品事实 |
| 有声样段 | 制作有代表性的连续段，包含真实画面、文字事件、镜头衔接和音乐落点 | 可播放样段和对应可编辑时间轴 | 通过动态与声音检查，静帧不能替代 |
| 完整粗剪 | 使用真实素材和必要代码动效，完成全片含片尾及实际声音 | 整片预览、镜头/任务进度、当前版本 | 时长符合目标；无缺段、空素材及遗漏片尾 |
| 审片修复 | 技术 QC、内容/重复审计、实际整片视听、独立复核；逐条修复问题 | 带时间码问题列表、修复前后版本、待复核状态 | 当前版本无未关闭 blocker；审核确实对应当前输出 |
| 交付 | 导出成片、字幕、封面、可编辑工程及清单；准备平台草稿 | 交付列表、版本/尺寸/声音状态、检查报告 | 文件完整可播放；内容、视听、技术分别有证据 |

正常阶段由 Agent 与审核任务持续推进，不要求用户逐阶段重复下令。用户可随时暂停、改稿和审片。方向实质冲突、关键主张无法判断、付费/新外传服务或发布才需要用户决定；已有授权持续沿用。

片型分支：
- 仅脚本/拍摄规划：brief → 来源与需求 → 拍摄脚本 → 现场采集安排 → 规划复核/交接；没有实拍素材也可完成，不启动成片渲染。
- 宣传/音乐文字片：先证据与故事链、音乐方向，再有声动态样段；不自动加旁白。
- 教程/访谈/纪录/已有视频改剪：按原话、动作与原声选段，保留指定内容和片尾；不强制广告节奏。
- 长片：先按章节组织；需要旁白时先冻结稿件再生成实测时间戳，段落与镜头保持稳定 ID。

技能现有 promo 阶段里的 voiceover.md 是稿件文件名，不代表必须配音。声音工作在方向/样段阶段就开始，后续 sound 阶段负责最终混音和复核，不能到整片渲染后才找音乐。

## 4. 产品界面安排

“素材库设置”继续负责导入、索引与服务配置；每个影片项目增加“制作”面板，承担阶段推进。制作入口放在项目内，不能让用户去设置里找当前片子的脚本和审片问题。

制作面板显示当前阶段、下一项具体工作、缺口、正在工作的 Agent/模型、任务数量及失败原因。状态按片型组织，规划项目不显示虚假的渲染进度。

脚本区可直接编辑并按段落批注；素材区展示匹配候选、原件预览、源区间和实际检查状态；画布展示分镜与风格；原生时间轴保持可直接剪辑。审片区点时间码跳转预览，显示问题所对应的镜头和版本。

任务卡展示输入版本、真实阶段、产物、开始/耗时、活动日志、取消/重试；不把模型逐 token 输出当作唯一进度。全片百分比只在分母可定义时显示，语义性任务显示状态而不是伪造百分比。中断、失败、等待素材、等待服务与等待用户分别呈现。

## 5. 技术接入：一个项目、一份阶段状态、一条执行时间轴

### 5.1 权威数据

- workflow.json 继续作为技能工作台的阶段、问题与审核记录源；Zfilm 读取并通过单一协调器更新，不另造一份会漂移的审批状态。
- film.html 是实际剪点、轨道、字幕与声音编排的权威；页面 window.film.frame(t) 决定镜头内状态。
- plan.json 保留故事、主张、镜头意图、素材需求等制作契约。进入剪辑后，执行时长/入出点从原生工程投影到审核视图，不能同时手改两份剪点。
- 稿件 ID → claim ID → asset ID → shot ID → clip ID → issue ID → export ID 保持稳定映射。用户在时间轴里的修改回写当前工程快照及影响记录。

### 5.2 项目目录（拟议）

应用工程根内保留 film.html、镜头 HTML 与 assets/；新增 production/ 保存 binding.json、workflow.json、dashboard.md、plan.json、research/、script/、direction/、storyboard/、review/、render/ 和 delivery/。运行队列与缓存放应用管理的位置，不塞进用户资产列表。

binding.json 明确 appProjectRoot、productionRoot、工程 ID、技能路径/内容指纹和运行配置，统一相对路径解析。制作项目素材清单引用工程资产，不再复制一份独立时间轴。

现有技能 initializer 固定创建 <root>/_video/projects/<name>，不能直接假装支持上述目录。第一期需增加明确目标目录的接入方式，或绑定已有工作台；新参数属于待实现能力。也要让导出工程包包含 production/ 的必要文档，排除缓存、凭据和无关个人风格库。

### 5.3 协调器与执行适配

拟议 WorkflowCoordinator 负责任务派发、输入版本、阶段硬门、单一写入、故障恢复和交付判定；不重做剪辑或渲染引擎。

AgentBridge 沿用当前选中的 Agent、模型及推理/快速模式选项，并记录实际加载的技能版本。项目开始先验证 video-production 与 Zfilm edit/media/canvas 指令的职责；避免技能默认目录与“仅操作当前工程”的要求冲突。

ZfilmEngineAdapter 复用现有编辑路径、look、范围 render 和导出队列。第一期由协调器显式调用这些能力；技能 wf.mjs 当前尚不能识别 Zfilm 工程，后续可增加 zfilm 引擎入口，不能将已有 html/Remotion 分支直接冒充已接入。

RuntimeProfile 显式发现 Node/Python/FFmpeg/FFprobe/浏览器/临时目录及服务能力，优先复用安装包运行时。技能目前存在个人工作区和 Chrome 固定路径，不能只改 VIDEO_WORKSPACE 就宣称桌面端兼容。以实际可执行检查为准，固定使用当前安装版本，避免自动 npx latest 导致版本变化。

其他引擎仅在特定镜头确有需要时作为可替换执行器；镜头音频仍按全片时间轴对齐，不建立第二条全片时间轴。普通剪辑不强制变成代码动画。

### 5.4 素材分两层处理

第一层入库：类型/尺寸/时长、文件身份、摘要与轻量标签，继承现有导入。第二层项目选片：只深审检索出的候选，得到动作事件、可用源入出点、声音价值、事实支持范围和已看/已听证据。无需等整个 552 文件库都完成深审才开始一个项目。

新增个人素材索引，消费 .zfilm-ai 元数据，与官方/社区检索保留来源区分。按原件 hash 关联派生副本，不能换裁切或文件名来绕过去重。文档超过预览范围时明确标记，项目确实需要全文再有界补读。

风格库按 style_id 关联同项的 Markdown、JPG、HTML/JS 和示例视频，区分“风格方法”“产品事实证据”“实际入片素材”。只注入选中的 1–3 项，保留许可与来源，工程包不复制整个风格库。索引成功不自动获得执行代码资格；实际改编代码动效须使用审查后的项目代码，原始导入代码和标记始终作为不可信数据处理。

### 5.5 可靠任务与修改恢复

任务记录至少包含 job/task ID、project ID、stage、依赖任务、输入工程 rev/内容指纹、Agent 配置、状态、attempt、输出清单/hash、错误类型和日志游标。

队列持久化；同项目协调器串行写状态并使用 revision 校验。多 Agent 可并行做无冲突的选片/稿件/事实复核，但只能提交产物与变更建议，由协调器合入共享状态，防止 lost update。

重试只针对失败/中断且输入仍有效的任务；已有成功结果按指纹复用，输入变化则生成新版本。已取消不自动复活；暂停停止新派发并安全落盘。取消请求要传递到 Agent、编码/渲染子进程，保留原件和已有合格版本。

第一期复用同输入异常中断续渲，修改后允许重渲全片。后续再实现 shot/segment 依赖图、镜头缓存与接缝合成。影响范围包括转场邻镜、关联声音及字幕；音乐结构、画幅、fps、全局字体/模板/混音改变时按依赖扩大失效，不能承诺每次都只重渲一个镜头。

### 5.6 审核与版本硬门

现有工作台仅追踪一个提交件和一个审核文件 hash，不递归覆盖其引用；reviewer 字符串也不证明真实独立复核。接入时增加审核包依赖清单，绑定工程 rev、实际输出 hash、素材/字幕/音乐/样式版本、审阅者角色和所用证据。

当前脚本新增 blocker 不会自动撤销已批准阶段，故每次全片制作和交付前必须重新检查所有相关未关闭 blocker、依赖变化与审核时效。源片未变但字幕/音乐/页面代码变化时，旧审核也应标为待复核。

按所依赖的功能实际看片与听音：只看抽帧的模型不能签署完整视听通过。独立复核由另一个具备相应能力的审阅会话或人工完成，留时间码问题；没有条件则准确标记“粗剪/技术通过/未独立复核”。自动检测黑场/静音只是候选问题，不能一概判错。

这些要求用于“工作流成片验收/交付”的判定。保留手工编辑、样段和标明状态的草稿导出，不用整片硬门阻止正常创作。

## 6. 实施顺序与完成标准

### P0：打通一支真实短片的完整闭环

交付：项目绑定与运行预检；当前 Agent 技能加载可验证；制作面板和持久化任务；按路径选择素材并补充实际选片记录；可编辑脚本/稳定镜头映射；原生有声样段/粗剪；带时间码审片修复；MP4＋字幕（需要时）＋可编辑工程＋审核/来源清单。

首期不依赖语义检索成熟，用户或 Agent 可按已知路径选择候选。使用已授权的真实录像、JPG、Markdown 风格说明、一个代码动效和实际音乐；必须完成一次改稿/改镜头及一次失败重试。由独立审阅者核对当前成片。以安装后的桌面应用真实项目验收，不只靠 mock、源码测试或安装包可打开。

### P1：把素材库变成真正可用的选片与风格系统

交付：个人 sidecar 索引与检索；候选预览；风格多文件关联；按需深审；源入出点/事实/许可/使用登记；转写服务预检；素材变更后的索引/审核失效。可在库未全部处理完成时持续选片制作。

### P2：提高修改效率及多画幅交付质量

交付：依赖指纹、段落/镜头产物、局部失效和接缝检查；多画幅版式变体；输出批次与交付清单。9:16 需要重排文字、主体和安全区并单独审片，现有 cover/contain 导出不能代表自动完成竖版设计。

### P3：长片与多角色协作

交付：章节稿件、句级/词级时间、角色分工、资源调度、分章审片、跨章连续性与全片声音复核；复用前几期的版本/恢复/审片基础。按实际资源限制并行，保证共享状态由单一协调器管理。

不以未经验证的工期承诺取代验收。每期完成后保留一个真实工程及证据包，再进入依赖它的下一期。

## 7. 必须覆盖的回归与验收

| 场景 | 必须观察到的行为 |
| --- | --- |
| Codex 未启用技能/运行时缺失 | 预检指出具体缺项，不能静默退回普通聊天或错误引擎 |
| 导入含 JPG/Markdown/JS/SVG/视频的真实目录 | 类型与文本/画面证据正确；源文件未变；文本不执行 |
| 个人素材语义检索 | 实际能找到带 sidecar 的入库项，结果可预览并复制入工程；不能只命中官方库 |
| Agent 返回格式错误或一个任务中断 | 展示失败位置/原因，只重试所需任务，不重复成功产物 |
| 重启应用 | 恢复当前阶段、产物、问题与任务；明确区分取消和中断 |
| 处理期间用户剪辑/锁轨 | 保留人工调整和锁定内容，冲突可解释，不覆盖别的镜头 |
| 修改素材/字幕/页面/音乐 | 依赖任务和旧审核准确失效，不显示过期“已验收” |
| 已通过阶段新增 blocker | 当前版本不能被工作流标为可验收交付 |
| 两个 Agent 同时提交 | 不丢问题/事件/产物；revision 冲突可检测和重放 |
| 同输入渲染异常中断 | 仅复用匹配输入/设置的完整块，不使用半成品 |
| 无旁白音乐片 | 不自动生成 TTS，有真实音乐及完整收尾 |
| 规划项目没有实拍文件 | 仍可交付可执行拍摄脚本/采集安排，不伪造素材或强制渲染 |
| 技术 QC 通过但没独立实听/观看 | 只显示对应检查通过，不能冒称成片验收通过 |
| 横版转竖版 | 实际检查字幕/主体/安全区和片尾，不能只验证尺寸 |
| 用户尚未授权新付费/外传服务 | 使用已有授权能力或记录等待，不自动发送素材/付费/发布 |
| 打包交付工程 | 换路径能打开、依赖齐全；无缓存/密钥/无关整库；版本可追溯 |

单元/契约测试覆盖状态机、映射、哈希、队列和错误分类；集成测试覆盖真实文件、安装版 Agent/剪辑/渲染；独立视听复核覆盖叙事、版式、声音与连续性。三者分别记录，不能互相替代。

## 8. 推荐的下一步

先实施 P0，让 Zfilm 形成可见、可恢复且可审片的“制作”面板，并用一个真实短片工程验证完整产出。P1 素材智能检索随后接入；P2/P3 建立在同一项目和时间轴上扩展。本轮不直接实现这些功能，也不启动测试片制作。
